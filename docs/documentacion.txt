Actualmente tenemos una aplicación web interna de Recursos Humanos desarrollada a medida para Talca.
Infraestructura técnica
Aplicación
- Backend desarrollado en Python con Flask.
- Arquitectura modular mediante blueprints:
  - Autenticación.
  - Dashboard.
  - Empleados.
  - Vacaciones y licencias.
  - Horas extra.
  - Noticias.
  - Documentos.
  - Sanciones.
  - Notificaciones.
  - Administración.
- Frontend renderizado con Jinja, HTML, Bootstrap, CSS y JavaScript.
- Diseño responsive para computadoras y celulares.
- Modo claro y oscuro.
- Identidad visual adaptada a Talca.
Base de datos
- Base principal en PostgreSQL.
- Acceso mediante SQLAlchemy.
- Tablas dentro del esquema rrhh.
- Información separada por módulos.
- Relaciones entre usuarios, empleados, documentos, solicitudes y movimientos.
- Migraciones SQL para cambios estructurales.
Integración con Trilay
- Conexión de solo lectura a SQL Server mediante pyodbc.
- Consulta controlada de columnas autorizadas.
- No se consulta ni copia la contraseña de Trilay.
- Sincronización automática hacia PostgreSQL.
- Ejecución programada cada hora.
- La sincronización es unidireccional:
Trilay → PostgreSQL → Portal RR. HH.
- Si Trilay no está disponible, el portal puede continuar funcionando con la información previamente sincronizada.
- Registro de última sincronización y procedencia de los datos.
Archivos y documentos
- Los metadatos se almacenan en PostgreSQL.
- Los archivos se guardan actualmente en el almacenamiento configurado en el servidor.
- Se organizan por módulo y empleado.
- Existe separación entre:
  - Documentación visible para el empleado.
  - Documentación enviada a RR. HH.
  - Archivo privado de RR. HH.
  - Recibos de sueldo.
  - Adjuntos de noticias y solicitudes.
Para una instalación productiva definitiva convendría utilizar un almacenamiento centralizado con respaldos, permisos y políticas de conservación.
Automatización
- Tarea programada de Windows para sincronizar empleados.
- Intervalo actual de una hora.
- Scripts de importación controlada para nóminas y vacaciones.
- Procesos idempotentes para evitar duplicaciones.
- Registro de errores y resultados de sincronización.
Seguridad
El sistema cuenta con:
- Inicio de sesión individual.
- Contraseñas almacenadas mediante hash.
- Cambio de contraseña desde el perfil.
- Usuarios activables y desactivables.
- Sesiones con tiempo máximo configurable.
- Cierre administrativo de sesiones.
- Roles y permisos por módulo y acción.
- Validaciones de permisos también en backend.
- Protección de cuentas administrativas.
- Auditoría de operaciones.
- Registro de usuario, fecha, endpoint, acción e IP.
- Registro de errores internos.
- Separación entre administrador operativo y administración técnica.
- Restricción de documentos privados.
Todavía corresponde definir para producción:
- Certificado HTTPS.
- Política formal de copias de seguridad.
- Recuperación ante incidentes.
- Cifrado y almacenamiento documental definitivo.
- Política de conservación de archivos.
- Firma electrónica validada por Legales.

Estado general
El proyecto ya funciona como un portal interno de RR. HH. con módulos operativos, base de datos, usuarios, documentos, solicitudes, comunicación y auditoría.
No es solamente un prototipo visual: tiene persistencia en PostgreSQL, autenticación, permisos, carga de archivos e integración con un sistema externo.
Para alinearlo completamente con el informe de la gerente faltan principalmente:
- Rol y asignación de supervisores.
- Aprobaciones en varias etapas.
- Bandeja unificada “Mis solicitudes”.
- Legajo de ingreso con documentación obligatoria.
- Cambios personales sujetos a validación.
- Registro obligatorio de lectura.
- Firma electrónica validada legalmente.
- Infraestructura productiva de respaldos, almacenamiento y recuperación.
